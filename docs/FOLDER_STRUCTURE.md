# Folder Structure & Dependency Graph

Understanding the repository layout is crucial for rapid onboarding. Studzens is currently structured as a monolithic repository containing both frontend and backend code.

## Root Directory

```text
studzens/
├── frontend/           # The Vite/React Web Application
├── backend/            # The Node/Express API Server (In Development)
├── database/           # Prisma Schemas, Migrations, and Seed Scripts
├── docs/               # Complete Engineering Documentation
├── scripts/            # Build and utility scripts
├── .github/            # GitHub Actions workflows (Planned)
├── package.json        # Root workspace configuration
└── README.md           # Project entry point
```

## Frontend Directory Dive (`/frontend`)

```text
frontend/
├── src/
│   ├── api/            # API Clients and Mock Data
│   │   └── mocks/      # Static data files (colleges.ts, exams.ts)
│   │
│   ├── components/     # React UI Components
│   │   ├── layout/     # Structural components (PageShell, Navigation)
│   │   └── ui/         # Reusable generic UI elements (Buttons, Inputs) - Planned
│   │
│   ├── contexts/       # React Context definitions (AuthContext, StudentProfileContext)
│   │
│   ├── hooks/          # Custom React Hooks (e.g., useLocalStorage)
│   │
│   ├── pages/          # Top-Level Route Components
│   │   ├── DashboardPage.tsx
│   │   ├── SearchPage.tsx
│   │   └── ...
│   │
│   ├── types/          # Global TypeScript interfaces
│   │
│   ├── App.tsx         # Root component & Routing configuration
│   ├── main.tsx        # React DOM rendering entry point
│   └── index.css       # Global styles and Tailwind custom classes
│
├── public/             # Static assets (favicon, raw images)
├── dist/               # Production build output (generated by Vite)
├── vercel.json         # Vercel deployment configuration (Routing rewrites)
├── tailwind.config.js  # Tailwind theme definitions
├── tsconfig.json       # TypeScript configuration
└── vite.config.ts      # Vite bundler configuration
```

## Database Directory Dive (`/database`)

```text
database/
├── prisma/
│   ├── schema.prisma   # The single source of truth for the Database Schema
│   ├── seed.ts         # Script to populate the database with initial college data
│   └── migrations/     # Auto-generated SQL files tracking schema changes over time
│
├── prisma.config.ts    # Database connection logic (Neon)
└── package.json        # Prisma dependencies
```

## Dependency Graph Highlights

- **`App.tsx`** depends heavily on **`AuthContext`** and **`StudentProfileContext`** to wrap the application in necessary state providers.
- **Pages (`src/pages/*`)** depend on **`src/api/mocks/*`** for data. This is an intentional architectural bottleneck. When the real API is ready, we only need to update the files in `src/api/` without modifying a single line of UI code in the `pages/`.
- **`PageShell.tsx`** acts as the layout container for almost all authenticated routes. Modifying this file affects the navigation structure of the entire application.
